# 自动作战与推演存档迁移到 IndexedDB

IndexedDB是浏览器内置的本地数据库，适合比localStorage更大的异步存档。本次不增加云端服务、登录、联网同步或付费依赖；数据仍属于当前浏览器、当前网站。

## 范围

| 数据 | 本次处理 |
| --- | --- |
| 当前作战自动存档 `junqi-battle-scene-v2` | 迁入IndexedDB |
| 更早的 `junqi-battle-state-v1` | 保留原恢复逻辑，读取时迁入 |
| 独立推演 `junqi-simulation-v1:*` | 打开或列出时迁入IndexedDB |
| 手动地图库/20个保存槽 | 原本就是IndexedDB，保留其数据库 |
| 单位与装备图鉴 `js/catalog-store.js` | 本次未迁移，仍沿用原来的存储与保护权限 |

新数据库名称为 `ama-local-saves`，包含 `records` 和 `save-index` 两个对象存储。前者保存原有兼容JSON文本，后者只保存名称、键和时间，避免为列出推演而读取全部大存档。

## 迁移与保存保证

- 先查IndexedDB；没有该记录时才读取对应localStorage键。
- 在一个读写事务中再次确认记录不存在，再写入存档及目录元数据。
- 旧localStorage的原始存档不删除、不改写。新版本以后只读取它们作为首次迁移备份；不会让旧备份覆盖新的数据库存档。
- 新写入在同一个IndexedDB读写事务内比较预期内容并写入。其他页面先保存了更新时，本次操作报冲突，避免覆盖。
- 只有事务 `complete` 后才更新内存、通知界面、报告成功或推进回合。请求自身的 `success` 不等于整个事务提交。
- 写入失败、中止或配额不足时，不发布候选推演结果，不推进阶段、回合、时间或弹药状态。保存锁会释放，允许处理错误后重试。
- 同一页面的重叠写操作被拒绝；不会把重复点击排队到后续阶段自动执行。
- 规则计算回调保持同步，不能把异步操作混入半完成的战斗计算。异步等待只在存档读写边界。
- 多标签页通过BroadcastChannel/少量localStorage通知元数据同步；不把大型存档继续写回localStorage。

新旧数据不会自动合并。升级后应关闭旧版本标签页再刷新。旧版本不知道新数据库的存在；回滚前应先从新版本导出需要保留的作战备份。

## 页面变化

保存时显示“保存中…”，确认写入完成后提示消失。写入未完成时离开页面会触发浏览器原有的离开确认。查看地图和选择单位无需等待磁盘写入；下一次会改变存档的操作要等当前保存完成。

构造和写入接口改为Promise：`await createBattleStore(...)`、`await createSimulation(...)`、`await openSimulation(...)` 以及 `await store.setTerrain(...)` 等。所有正在使用的编辑器、地形笔刷、单位拖放、地图库、推演控制和范围攻击工作台已接入等待逻辑。只读快照和算法查询保持同步。

作战JSON导入上限从5 MB调整为128 MiB（与数据库配额分开）。保存失败时仍可导出最后已确认的有效场景。导出备份功能保留，IndexedDB也不是无限容量或云备份。

## 验证

```sh
npm ci
npm test
node tests/compare-performance.mjs /absolute/path/to/baseline-checkout
```

测试使用 `fake-indexeddb` 验证真实的异步请求、读写事务及中止行为，不依靠伪装成同步Map的存档实现。开发依赖不参与网站运行。

覆盖旧存档逐字保留、新数据库优先、迁移中途失败后的原子回滚、6 MiB存档、localStorage写入配额不足、并发写入冲突、损坏存档恢复保护、刷新恢复、大JSON导入导出、保存中状态及写入失败后的正式阶段/回合不推进。地形鼠标入口、撤销/重做、损管、救助、侦察和范围攻击回归测试继续运行。

本次仍会在主线程进行JSON序列化和规则计算；IndexedDB解决大存档后端及同步磁盘写入的问题，不代表所有计算卡顿都已消除。Web Worker、分块地形和差量撤销属于后续优化。
