# 性能优化与大地图精度

> 更新：当前作战自动存档与独立推演存档已迁移到IndexedDB；迁移、异步接口和验证见[INDEXEDDB.md](INDEXEDDB.md)。下文的早期localStorage基准记录保留作历史对照。

这次修改减少重复的界面读取、地形复制与绘制工作，并提供7200×7200格地图的精细编辑数据格式。战斗公式、硬币判定、侦察规则、地形阻挡、设备损管、救助时机与存档事务校验均保留。

## 主要变化

- 自定义模式增加只读场景快照。同一次状态更新中的多个界面读取可共用快照；原来的 `getScene()` 仍返回独立可变副本。
- 推演缓存经过阵营和迷雾过滤的观察快照，不缓存或返回外方的完整运行状态。提交后缓存自动失效。
- 推演提交前后直接比较已读取的原始存档文字，避免重复解析、初始化同一存档；同revision的外部更改、嵌套保存、保存失败仍受保护。
- 不可变的地形和初始场景可以在事务间共享。单位快照、事务候选状态及结束阶段仍经过原来的校验。
- 选择单位时只更新详情和高亮，不重建整个列表和所有地图图标。
- 连续同类地形三角形合并成SVG路径，保留绘制顺序和全部传入三角形；在平坦81×81顶点地图中，12800个面元素降至50条路径。
- 绘制依据视口和缩放选择显示细节。移动、视线、武器地形线和鼠标拾取始终查询原始完整网格，不使用显示LOD。
- 平滑笔刷只复制所需邻域；其他笔刷不再为每个鼠标采样复制整张高度数组。
- 地形拾取沿投影视线检查实际相交单元，避免每次指针移动遍历所有网格。

## 7200格地图

在“地図と地形”中设置：

| 项目 | 值 |
| --- | --- |
| 幅 / 高さ | 7200 / 7200 |
| 列数 / 行数 | 7201 / 7201 |

7201个顶点对应7200个间隔。地图坐标与原有单位换算保持不变；没有缩小地图范围，也没有删去精细编辑数据。缩小时显示概览，放大后显示更细网格，最高缩放从3.5提高至32。

大网格使用 `terrain.version = 2`：基底保存原始地形快照，`vertices` 仅保存实际编辑的细网格顶点，每项记录高度、河流和浅海标记。没有编辑的顶点按原地形的三角面插值读取，不提前分配5185万个数组元素。旧版 `version = 1` 存档仍可读取、导入和编辑。

更改采样网格与原有“调整网格”一样，会按新节点插值；在同一网格下更改等高线间隔不会增加嵌套或丢弃已有精细编辑。新保存格式不能由旧代码读取，应先保留旧存档导出备份，再使用此分支。

## 验证

```sh
node --test tests/performance-and-terrain.test.mjs
node tests/compare-performance.mjs /absolute/path/to/baseline-checkout
```

对照基线：`251f1f91508d70f15c226f770e7f36c918d21663`。

- 31项自动测试通过；其中还运行项目原有的设备、损管、救助和范围攻击回归测试。
- 与基线进行938次确定性对照：100次笔刷状态、300次视线判定、300次完整攻击线结果、238条海面路线，结果一致。
- 验证7200格地图上的单格山体不会被规则查询漏掉，精确拾取可命中该山体；显示LOD不修改存档。
- 验证旧地图无损往返，大地图的编辑、保存、导出、导入和重新打开。
- 验证观察快照不泄露未识别单位的资料；保存失败不推进状态，跨页和嵌套保存不会被旧事务覆盖。
- 所有修改和新增的JavaScript模块通过语法检查，`git diff --check`通过。

一次Node基准（40艘测试舰、内存模拟localStorage）：缓存预热后的25次界面场景读取从约89ms降到约0.006ms；5次提交从约37ms降到约28ms。这个数据只衡量代码路径，不能等同于真实浏览器FPS或磁盘存档速度。运行脚本可复测；首次快照仍需要计算侦察和迷雾。

7200格地图的创建加一次半径5的局部笔刷在同一次运行约4ms，保存81个精细顶点，JSON约55KB。这只验证局部编辑，不代表整张地图全部密集编辑后的内存和存储开销。

## 当前限制与验证边界

- 作战和推演现已使用IndexedDB，但仍受浏览器配额和磁盘空间限制，导出备份继续保留。
- 细网格按实际编辑数量增长；大半径笔刷和极密集编辑仍需进一步做后台计算与分块存储。
- 基底最多允许16层，防止递归存档失控；相同尺寸/精度的重复应用不会增加层数。
- 此环境的Chromium无法启动，远程浏览器也无法访问本地预览，因此尚未完成真实浏览器的视觉、拖动、缩放和撤销/重做验收。当前提交适合分支审核，不应视为完成浏览器性能验收。
- 全库语法扫描发现基线就存在的 `js/app.js:192` 多余闭合符号。该旧入口未被当前HTML引用，本次没有修改它；这与已修改模块的语法检查分开记录。
