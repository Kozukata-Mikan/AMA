# 性能优化与大地图精度

> 更新：当前作战自动存档与独立推演存档已迁移到IndexedDB；迁移、异步接口和验证见[INDEXEDDB.md](INDEXEDDB.md)。下文的早期localStorage基准记录保留作历史对照。

这次修改减少重复的界面读取、地形复制与绘制工作，并提供7200×7200格地图的精细编辑数据格式。战斗公式、硬币判定、侦察规则、地形阻挡、设备损管、救助时机与存档事务校验均保留。

## 主要变化

- 自定义模式增加只读场景快照。同一次状态更新中的多个界面读取可共用快照；原来的 `getScene()` 仍返回独立可变副本。
- 推演缓存经过阵营和迷雾过滤的观察快照，不缓存或返回外方的完整运行状态。提交后缓存自动失效。
- 推演提交前后直接比较已读取的原始存档文字，避免重复解析、初始化同一存档；同revision的外部更改、嵌套保存、保存失败仍受保护。
- 不可变的地形和初始场景可以在事务间共享。单位快照、事务候选状态及结束阶段仍经过原来的校验。
- 选择单位时只更新详情和高亮，不重建整个列表和所有地图图标。
- 连续同类地形三角形合并成SVG路径，保留绘制顺序和全部传入三角形；在平坦81×81顶点地图中，12800个面元素降至50条路径。
- 绘制依据视口和缩放选择显示细节。移动、视线、武器地形线和鼠标拾取始终查询原始完整网格，不使用显示LOD。
- 平滑笔刷只复制所需邻域；其他笔刷不再为每个鼠标采样复制整张高度数组。
- 地形拾取沿投影视线检查实际相交单元，避免每次指针移动遍历所有网格。

## 7200格地图

在“地図と地形”中设置：

| 项目 | 值 |
| --- | --- |
| 幅 / 高さ | 7200 / 7200 |
| 列数 / 行数 | 7201 / 7201 |

7201个顶点对应7200个间隔。地图坐标与原有单位换算保持不变；没有缩小地图范围，也没有删去精细编辑数据。缩小时显示概览，放大后显示更细网格，最高缩放从3.5提高至32。

大网格使用 `terrain.version = 2`：基底保存原始地形快照，`vertices` 仅保存实际编辑的细网格顶点，每项记录高度、河流和浅海标记。没有编辑的顶点按原地形的三角面插值读取，不提前分配5185万个数组元素。旧版 `version = 1` 存档仍可读取、导入和编辑。

更改采样网格与原有“调整网格”一样，会按新节点插值；在同一网格下更改等高线间隔不会增加嵌套或丢弃已有精细编辑。新保存格式不能由旧代码读取，应先保留旧存档导出备份，再使用此分支。

## 当前限制与验证边界

- 作战和推演现已使用IndexedDB，但仍受浏览器配额和磁盘空间限制，导出备份继续保留。
- 细网格按实际编辑数量增长；大半径笔刷和极密集编辑的实际负载仍需用用户场景测量。
- 基底最多允许16层，防止递归存档失控；相同尺寸/精度的重复应用不会增加层数。
- 此环境的Chromium无法启动，远程浏览器也无法访问本地预览，因此尚未完成真实浏览器的视觉、拖动、缩放和撤销/重做验收。当前提交适合分支审核，不应视为完成浏览器性能验收。
- 全库语法扫描发现基线就存在的 `js/app.js:192` 多余闭合符号。该旧入口未被当前HTML引用，本次没有修改它；这与已修改模块的语法检查分开记录。

## 后台计算、地形分块和推演显示（后续更新）

- 模块Worker处理移动结算、攻击阶段结算、特殊阶段与回合结束，以及地形笔刷、尺寸调整。Worker直接调用原有规则模块。主线程仍负责事务校验和IndexedDB确认；失败不提交，也不在前台自动重算随机结果。无Worker能力时才使用兼容路径。
- 地形编辑使用v3：每块32×32顶点，未编辑处继承原始基底。只复制触及的块，校验过的冻结基底和未改块可共享。v1/v2旧存档仍可导入；7200×7200格上限和精确规则查询保持不变。
- 一笔撤销仅记录改过顶点的前后差分；尺寸调整保留冻结结构引用。保存失败不移动撤销栈，外部换图会清空历史。撤销历史仍为20步，不跨页面保存。
- 这是内存中的地形分块和增量编辑；磁盘存档仍以完整场景JSON原子写入IndexedDB，并未改成逐块数据库写入。首次打开、序列化、侦察预览及SVG绘制仍可能占用主线程。
- 推演新增距离网格按钮，支持XY和XY/XZ/YZ参照平面，显示实际间距（XY每5格1km、Z每格100m）。缩远时自动疏化，放大恢复指定间隔；网格不修改地形。
- 昼夜显示复用既有时段边界；黎明红光来自东侧+X，夕烧来自西侧−X。地形和背景调整亮度，单位与文字保持可读，环境规则不变。
- 新增真实独立线程协议、完整空计划回合对照、失败不保存、10类笔刷分块撤销、冻结块共享、最大网格显示数量及时间边界测试。全部82项自动测试通过，并对本次改动前版本完成938项确定性算法对照。大型列表与大型场景的实际浏览器压力测试等待用户JSON，以上结果不代表已完成该项验收。

## 大战役侦察与历史记录优化（2026-11-16）

基线为 `73caad99169571ff0ac03dc2b357f2bcd5aa708c`。使用同一份116舰、28编队战役与74单位图鉴，在同一Node环境中通过真实Worker线程运行生产结算代码；IndexedDB使用内存实现。总时间包含规则、事务校验、保存和观察快照，不包含浏览器DOM绘制或真实磁盘等待，不能直接作为用户电脑上的秒数。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 自动行动首回合 | 72.48秒 | 6.54秒 |
| 自动行动第2、3回合 | 未测 | 5.63、5.37秒 |
| 待机前3回合平均 | 8.05秒 | 4.64秒 |
| 第3回合存档JSON | 5.71 MB | 2.13 MB |
| 历史记录每回合增量 | 约1.34 MB | 约87 KB |

连续10个待机回合为4.4～5.1秒；第10回合存档约2.73 MB。数据为十进制MB，保留全部报告，不截断历史。

实现要点：

- 单次侦察查询内复用观察者设备状态，固定规划快照内按阵营复用可见性。缓存不跨查询保存，移动、受损、修复、时间与地形变化仍重新计算。
- 已提交历史使用模块私有标记和深度冻结共享，减少整个场景复制时重复展开旧战报。未知或外部提供的可变记录仍独立复制；不跳过原有校验。
- 存档及Worker消息对设备前后状态使用无损字典编码，相同JSON仅保存一份。读取时恢复完整语义，旧版未编码存档仍可读，下一次保存写为新格式。损坏索引和未知版本拒绝读取，不覆盖源存档。
- 保留规则、随机判定、迷雾白名单、原子保存和并发冲突检查。新格式需当前代码读取，旧版程序不支持该字典标记。

验证：122项测试通过。使用固定随机数对原始战役与近距离交战场景逐阶段比较，20个阶段的完整状态、公开观察结果及错误均与基线一致；覆盖50条命中报告、4个受损目标、2次碰撞和特殊阶段报告。用户JSON不随仓库提交。
